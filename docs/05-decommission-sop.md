# Decommissioning the CloudGenius AI Azure Administrator POC

> **DANGER — DESTRUCTIVE OPERATION.** This removes **every** resource currently in the targeted resource group, not just resources originally created by the sample scripts. Review the entire inventory and any unrelated resources before approving. Storage data loss may be irreversible.

## Script

[03-Decommission-CloudGeniusAI.ps1](../scripts/03-Decommission-CloudGeniusAI.ps1) is the **separate cleanup script** for the environment created by the first two scripts.

**Its scope is intentionally limited:** select and verify one subscription, inventory and delete one resource group, verify group absence, then optionally purge **one matching** soft-deleted Foundry AIServices account after separate confirmation.

It does **not** affect other resource groups, GitHub files or repository history. Billing history, Azure Activity logs, retention records and some service-specific recoverable data can remain.

## Before running

1. Complete any demos and back up any important data in `rg-cloudgenius-ai-dev`.
2. Confirm you have **resource group delete** permissions and rights to purge Foundry if desired.
3. Confirm the Azure CLI is installed and run `az login`.
4. Check for any unexpected resources manually:

~~~powershell
az resource list --resource-group rg-cloudgenius-ai-dev --output table
~~~

5. Review the script in GitHub, including the subscription and Foundry name taken from the locally generated config.
6. If downloaded Windows scripts are blocked, inspect them, then use `Get-ChildItem ".\scripts\*.ps1" | Unblock-File` if your local policy permits.

## Run after cloning this repository

If you ran Script 1 from this same clone, `scripts/cloudgenius-ai-config.json` will be present. The cleanup script automatically loads that exact configuration:

~~~powershell
& ".\scripts\03-Decommission-CloudGeniusAI.ps1"
~~~

The local config is **not** committed to GitHub. If you cloned this repository on a *different* computer, supply the identifiers used in your deployment explicitly:

~~~powershell
& ".\scripts\03-Decommission-CloudGeniusAI.ps1" -SubscriptionId "<YOUR-SUBSCRIPTION-ID>" -ResourceGroup "rg-cloudgenius-ai-dev" -Location "eastus" -FoundryName "<YOUR-ACTUAL-CGFOUNDRY-NAME>"
~~~

Replace the placeholders; do not literally type angle-bracket values. For the first demonstrated lab, the final successful Foundry name was `cgfoundry170463`; other users' Foundry names differ.

To delete only the resource group and intentionally skip the separate Foundry purge:

~~~powershell
& ".\scripts\03-Decommission-CloudGeniusAI.ps1" -SkipFoundryPurge
~~~

## What happens in detail

| Stage | Action | Failure/confirmation behavior |
| --- | --- | --- |
| Configuration | Read `cloudgenius-ai-config.json` or require explicit identifiers | Stop if missing, unexpected or conflicting |
| Subscription | `az account set`, then compare `az account show` ID | Stop on mismatch |
| Inventory | Show **all** current resources in the target RG | Stop if enumeration fails |
| Deletion approval | Require exact text `DELETE rg-cloudgenius-ai-dev` | Nothing deleted if declined |
| RG delete | `az group delete --name <group> --yes` | Wait for operation, fail on CLI error |
| RG verification | `az group exists` must return `false` | Throw if RG still exists |
| Foundry soft-delete | Check deleted account matches resource name, location, subscription and original group | No guessing other Foundry accounts |
| Purge approval | Require `PURGE <foundry-name>` | RG deletion already completed; Foundry remains recoverable if declined |
| Purge | `az cognitiveservices account purge` | Throws on CLI failure, polls listing for propagation |
| Final | Check RG absence again | Report project RG cleanup result |

### Where did the names come from?

`cloudgenius-ai-config.json` is generated by Script 1, beside the other scripts. It contains the subscription ID, region, resource group, Foundry name, project and model deployment alias. It does not contain the Foundry API key.

The Storage name created by Script 2 (e.g. `cgaistore610655`) is not required as a separate deletion target: the entire RG, including that Storage account and any other resources currently in the RG, is removed as one Azure operation.

### Why the extra Foundry purge?

Foundry AIServices can be **soft-deleted** after group removal, leaving a recoverable account record. Azure CLI's `az cognitiveservices account list-deleted` and `purge` operations address this separately. The cleanup script confirms before purging and explicitly checks listing state. Some Azure back-end listings can lag; check again later if Azure hasn't yet shown the expected entry.

**Other limitations:** Storage data-plane recovery/snapshots, service-specific retention, subscription-level permissions/registrations, billing and audit data are not purged by this script. It is incorrect to promise that absolutely no records remain.

## Important safety notes

- **Never run against a shared resource group** containing resources you want to keep.
- The script does **not** blindly enumerate and purge all soft-deleted Cognitive Services accounts.
- Foundry purge cannot recover data. Perform it only after verifying you will not need that resource.
- Project deletion doesn't remove the user's GitHub repository or their local files.
- Rerunning Script 1 after successful deletion with stale config may fail; remove stale local config **only after checking the real Azure state** and intending a fresh environment.
- Use an organization-approved change ticket and retention policy for production workloads.

## Optional post-run verification

~~~powershell
az group exists --name rg-cloudgenius-ai-dev
az cognitiveservices account list-deleted --output table
~~~

Expected group existence is `false`. Carefully match the Foundry account name and original resource-group identity rather than treating any deleted account in the subscription as this project's account.
